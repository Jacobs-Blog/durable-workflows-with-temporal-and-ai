# TemporalRSSReader

A durable workflow that reads an RSS feed, asks a local AI agent whether each article is worth reading, and lets you decide what to keep.

Everything is orchestrated by [.NET Aspire](https://aspire.dev).

## How it works

1. **Start run** in the reader triggers `ReviewBatchWorkflow`. No runs start on startup or on a timer.
2. `FetchFeedAsync` downloads the feed. Link-blog posts (like Alvin Ashcraft's daily "Dew Drop") are expanded into one item per link.
3. For each unique link not already in the inbox or Saved articles, a **Microsoft Agent Framework** agent backed by local **Ollama** returns `ShouldRead`, `Score` (0–10), and a one-sentence `Reason`, judged against your interests and past feedback.
4. As each article is scored, its child workflow publishes it to the inbox in Postgres using **Marten**, then starts a `review-decision` activity that stays pending without occupying a worker slot. You can review early results while the rest of the batch is still scoring.
5. **Accept** or **Reject** in the review inbox completes that pending activity. A separate activity moves an accepted article to **Saved articles** or deletes a rejected article and its feedback. **Add feedback** is separate: mark an article 👍 or 👎 and optionally say why.
6. The batch waits for its article workflows, but later manually triggered batches can run independently. The new review path applies to new runs; previously published inbox entries still use the original decision path.

Work is spread over three worker replicas. If a worker crashes, Temporal can retry its unfinished activities on another one.

## Requirements

- .NET 10 SDK
- Docker
- [Ollama](https://ollama.com) running locally with the model pulled (default `qwen3:8b`)

## Running

```
cd src/TemporalRSSReader.AppHost
dotnet run
```

Or run the AppHost from your IDE. Run **only one copy** at a time, or you get duplicate containers and workers.

From the Aspire dashboard you can open:

- **web**: the reading list table
- **temporal**: the Temporal UI (workflow runs and activity history)
- **aspirec4-server**: a live architecture diagram generated by [AspireC4](https://github.com/purview-dev/aspirec4)

Use **Start run** in the reader to queue a run with the configured feed settings. Work happens in the background; articles already in the inbox or Saved articles will be skipped.

To see a review wait in Temporal UI, open a `ReviewBatchWorkflow` run and follow an article's child workflow link. Look for **WaitForDecision** (activity ID `review-decision`). It is pending asynchronous completion, not manually paused, and can wait up to 365 days. After accepting or rejecting the article, the child history shows **WaitForDecision** complete and **ApplyDecision** run.

## Configuration

| Setting | Where | Default |
|---|---|---|
| `Feed:Url` | `Worker/appsettings.json` | `https://www.alvinashcraft.com/feed.xml` |
| `Feed:Interests` | `Worker/appsettings.json` | DDD, Aspire, Temporal, Critter Stack, Marten, JasperFx, Polecat, Jeremy Miller |
| `Feed:MaxItems` | `Worker/appsettings.json` | `1` top-level feed item per run; a link roundup can expand into many articles |
| `Ollama__Model` | `AppHost/AppHost.cs` | `qwen3:8b` |
| `Ollama__Endpoint` | `AppHost/AppHost.cs` | `http://localhost:11434` |
| Worker replicas | `AppHost/AppHost.cs` | 3 |

The worker updates the stored Temporal schedule on startup, so changing the feed or interests takes effect on the next run.

## Reviewing and training data

Saved thumbs-up and thumbs-down votes help guide future recommendations. When scoring an article, the worker gives the local model up to four recent examples of each verdict, including any comments, alongside your configured interests. Accepted articles keep their feedback; rejected articles no longer contribute. This changes what the model sees in its prompt; it doesn't retrain the model or immediately rescore articles you've already reviewed.

In the inbox you can filter by “not yet reviewed”, “reviewed”, or “where I disagree with the AI”. These filters refer to feedback, not whether you've accepted or rejected an article. `/api/export` downloads JSONL for articles with a vote in either the inbox or Saved articles, including your interests, the AI's decision, and your verdict and reason.

## Data

- Inbox reviews and accepted articles are stored in separate Postgres tables (volume `reviews-data`). No rejection list is kept, so an article may appear again if it is still in the feed.
- Temporal history is stored separately in the `temporal-data` volume and may retain feed and scoring payloads after a Postgres rejection.

To reset the app, stop the AppHost and run `docker volume rm reviews-data temporal-data`. This permanently removes the inbox, saved articles, feedback, and Temporal schedules and history. Restart the AppHost to recreate both volumes, then click **Start run** when ready.
